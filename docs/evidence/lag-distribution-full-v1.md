# A6: распределение technical lag на full-v1

Анализ выполнен на нормализованном snapshot `full-v1` и рассчитанных
метриках technical lag. В dataset входят 60 007 npm-пакетов, 5 350 358 версий и
76 871 904 декларации зависимостей. Единица анализа — dependency requirement из
npm-манифеста, а не установленная зависимость или ребро deps.dev.

Входы проверены по manifests до начала расчёта. SHA-256 normalization manifest:
`b4560e99e8a3a4e83e3799fea3989d5de175d08d64766cdc4dd626c1909254b9`;
SHA-256 technical lag manifest:
`27a024bb8c588a30a73630cdef777cbd55dba307803e7c738497bb98b9f4a096`.

Воспроизводимый запуск из корня репозитория:

```bash
analysis_output_root="$(mktemp -d)"
.venv/bin/python -m analysis.lag_distribution \
  --dataset-id full-v1 \
  --normalized-dir data/datasets/full-v1-normalized/normalized \
  --lag-dir data/datasets/full-v1-technical-lag/technical_lag \
  --output-dir "$analysis_output_root/lag-distribution"
```

Параметры статистики по умолчанию: 2 000 bootstrap-повторов и seed `20261027`.

## Покрытие

| Показатель | Строки | Доля всех requirements |
| --- | ---: | ---: |
| Все dependency requirements | 76 871 904 | 100% |
| Technical lag рассчитан | 11 806 892 | 15,3592% |
| Исключены с явной причиной | 65 065 012 | 84,6408% |
| Есть ненулевой version lag | 1 919 610 | 2,497% |

Исключённые наблюдения не считаются зависимостями без lag. Основные причины
исключения — непригодная версия потребителя или дата публикации (44 001 346 строк)
и тип зависимости вне основного анализа (19 915 941). Ещё 714 130 требований не
имели версии, удовлетворяющей constraint на момент наблюдения, а для 233 668 не
было истории dependency package.

## Распределение lag

Среди 11 806 892 пригодных наблюдений 9 887 282 (83,74%) не имели lag, а
1 919 610 (16,26%) отставали хотя бы на одну версию.

| Доступное обновление | Строки | Доля пригодных | Доля наблюдений с lag |
| --- | ---: | ---: | ---: |
| patch | 185 116 | 1,57% | 9,64% |
| minor | 447 598 | 3,79% | 23,32% |
| major | 1 286 896 | 10,90% | 67,04% |
| нет доступного обновления | 9 887 282 | 83,74% | — |

Медианы version lag и time lag по всем пригодным наблюдениям равны нулю, потому
что большинство dependencies не отстают. Среди наблюдений с положительным version
lag медиана составляет 4 версии, p75 — 12, p90 — 28. Положительный time lag
рассчитан для 1 790 325 строк: медиана — 305,97 дня, p75 — 681,19 дня,
p90 — 1 215,56 дня.

Положительный version lag не всегда означает положительный time lag: у 129 196
успешных строк порядок публикации SemVer-версий не монотонен, ещё у 89 строк
сравниваемые версии имеют одинаковый timestamp. Эти наблюдения сохранены и отмечены
в диагностике, а не исправлены искусственно.

## Связь с характеристиками пакета

Для каждой версии consumer package сначала рассчитан средний version lag по её
пригодным requirements. Затем значения признака и mean version lag усреднены по
версиям одного пакета. Spearman correlation рассчитана между этими двумя
package-level величинами, чтобы пакеты с большим числом исторических релизов не
доминировали в оценке. Доверительные интервалы получены 2 000 bootstrap-повторами.

| Характеристика | Пакетов | Spearman rho | 95% CI | Интерпретация |
| --- | ---: | ---: | ---: | --- |
| Возраст пакета | 40 120 | 0,205 | [0,195; 0,215] | Более старые пакеты в среднем немного чаще имеют lag |
| Stable releases в год | 36 376 | -0,001 | [-0,011; 0,009] | Наблюдаемой монотонной связи нет |
| Число production dependencies | 40 120 | 0,387 | [0,378; 0,396] | У пакетов с большим числом зависимостей lag заметно выше |

В анализ вошли 40 120 consumer packages, для которых technical lag удалось
рассчитать хотя бы для части requirements. Release cadence определён для 36 376
из них с достаточной историей stable releases.

Самая выраженная из трёх связей наблюдается для числа production dependencies.
Возраст связан с lag слабее, а монотонной бивариатной связи с release cadence не
обнаружено. Это описательные корреляции: они не показывают причинный эффект и могут
отражать различия между возрастными когортами, назначением и популярностью пакетов.

## Вывод

Technical lag не является состоянием большинства пригодных dependency
requirements, но и не редок: он присутствует примерно в каждой шестой строке.
Две трети случаев lag требуют уже major-обновления, а типичное положительное
отставание составляет 4 версии или около 306 дней. Наиболее заметный доступный
признак повышенного lag — большое число production dependencies у пакета;
монотонной бивариатной связи с release cadence не обнаружено.

Вывод относится только к исторически реконструируемым декларациям npm, версии
которых сохранились в текущем Registry snapshot. Он не описывает фактически
установленные версии, lock-файлы или resolved dependency graph.
